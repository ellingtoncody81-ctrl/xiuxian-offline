# 《忆游十三道》离线单机化改造（技术展示 / Toolkit）

把这款 **修仙题材放置手游《忆游十三道》**（H5 / Cocos 客户端 + Node(Koa) 服务端 + MySQL/Redis）
改造成 **完全离线、双击即跑的单机版** 的改造层代码与文档。

> **本仓库只包含原创改造层代码与文档。**
> 不含任何游戏客户端 / 服务端资源，也**不提供任何下载链接**；
> 完整可运行包**不对外发布** —— 这里公开的是「怎么改」，不是「改好的成品」。
> 需要的原版文件请自备，步骤见 [docs/如何组装运行包.md](docs/如何组装运行包.md)、
> 全部改动点见 [docs/改造点清单.md](docs/改造点清单.md)。

## 一、项目概况
- **游戏**：**《忆游十三道》**（放置修仙手游，H5 客户端 + 常驻服务端 + MySQL/Redis，含内购、运营后台、活动排期等完整线上体系）
- **关系声明**：这是**非官方、非商业**的个人技术改造项目，与游戏厂商 / 发行商 / 运营方**没有任何关系**，也未获得其授权或认可
- **类型**：放置（挂机）手游 —— 放置推图 / 仙侣养成与合成 / 竞技场斗法 / 仙盟 BOSS / 榜位挑战 / 洞天 / 邮件与附件 / 称号与头像框
- **原始形态**：H5 客户端（Cocos）+ Node(Koa) 服务端 + MySQL + Redis，多进程、需要常驻服务
- **改造目标**：**离线单机** —— 无外部数据库、无 Redis、无外网依赖，一个目录双击即玩；并且让"单机的世界"看上去是活的
- **改造范围**：运行形态（内嵌服务端）、存储替换（JSON）、垫片层（11 个模块）、假人系统、AI 接入、客户端少量补丁、离线工具

## 二、玩法特点（被改造的目标游戏）
| 系统 | 说明 |
|---|---|
| 放置挂机 | 离线收益、挂机推图、境界成长 |
| 仙侣系统 | 抽/合成/继承经验；**品质保底**（失败累计到阈值必出真仙侣）；主技能 + 协战技能双线成长 |
| 竞技场（斗法） | 按积分梯度匹配，名次与战力挂钩 |
| 仙盟 BOSS | 全盟输出打同一目标，按难度递增强化 |
| 榜位挑战 | 榜单对手按名次生成，名次越高强度越高 |
| 洞天 / 邮件 / 称号头像框 | 资源产出、附件发放、外观收集 |

## 三、技术亮点
1. **服务端内嵌化**：Koa 直接跑在 Electron 主进程里，`start({dbDir})` 后打印 `SOLO_READY <port>`；没有独立服务进程、没有端口占用冲突处理成本
2. **存储全量替换**：MySQL 表 → 纯 JSON 分库文件（启动自动备份）；Redis → JSON 快照 + **语义垫片**（zset / kv 按官方契约实现），登录链路 0 改动
3. **垫片层（运行时注入）**：11 个 `shim/_solo_*.js`，用 require 钩子包裹官方模块导出的函数，**在运行时接管行为** —— 绝大多数改造因此不需要改官方文件；含离线启动、假人系统、AI 网关、GM 邮件、红点、战力自测
   - 只有少数「必须在函数内部生效」的点位（如登录链路里补发称号、战斗阵容里换技能数据）采用**带标记的定点插入 / 替换**：服务端 **18 个**官方文件（另有 2 个存储层文件整文件替换）、客户端 **9 个**，逐条见 [docs/改造点清单.md](docs/改造点清单.md)
4. **假人系统（离线世界的"活人感"）**：200 个假人（分盟、行为驱动）+ 100 个活跃 NPC；会聊天、会挑战、会参与仙盟 BOSS，行为分布与真人相近（避免"离线后榜单全空"的崩塌感）
5. **AI 网关 + 降级**：统一 `ask({system,user,maxTokens})` 接口，兼容 Anthropic / OpenAI 协议，可指向自建代理；**未配置 key 时自动退回内置台词库**（0ms 跳过、不报错）
6. **外置配置与容错解析**：配置文件查找四级回退（环境变量 → 游戏根目录 `ai-config.json` → 同目录 `.txt` → 旧位置），支持 `key=value` 纯文本写法与注释行
7. **客户端最小补丁**：官方 H5 构建共 **1.26 万个文件，只需改 9 个**（登录链路、资源加载、文案与条目调整、引擎兼容性小改）—— 逐条见 [docs/改造点清单.md](docs/改造点清单.md)
8. **离线工具**：由游戏数据表生成的查询页（合成概率 / 配方反查 / 等级表），纯静态、无后端
9. **工程化**：Conventional Commits + `commit-msg` 校验 hook + 版本 tag + CHANGELOG

## 四、仓库结构
```
shim/          垫片层（11 个运行时模块）
  server_overrides/  两份「存储替换」实现（把官方连 Redis/Mongo 的封装换成 JSON 版）
launcher/      Electron 启动器（窗口 / 本地静态服务 / 页面注入）
patches/       客户端改造规则（9 个文件 / 121 条锚点规则，不含原版文件）
tools/         `apply_client_rules.py`（施加客户端规则）+ commit-msg 校验钩子
docs/          架构文档 · 改造点清单 · 自己搭一套的步骤
```
